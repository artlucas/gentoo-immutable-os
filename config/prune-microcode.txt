# Intel CPU microcode signatures pruned from the image (stage 40, BEFORE dracut).
# One family-model prefix per line, matched as usr/lib/firmware/intel-ucode/<prefix>*.
# Lines starting with # ignored.
#
# WHY THIS FILE EXISTS AT ALL, AND WHY IT IS WORTH MORE THAN ITS SIZE SUGGESTS.
# sys-firmware/intel-microcode installs 315 signature files, 34.5 MiB, covering every Intel CPU
# from the Pentium 4 to the current Xeon. dracut's --early-microcode packs all of them into the
# initrd's EARLY CPIO — which the kernel reads before it can decompress anything, so that cpio is
# stored UNCOMPRESSED, by design. Measured on the 0.2.2 UKI: 34.8 MiB of a 135.5 MiB UKI is this
# tree, a quarter of the whole boot artifact, and every A/B update downloads it. A megabyte cut
# here is a megabyte off the ESP and off every update; a megabyte cut from the root filesystem is
# worth roughly a third of that after EROFS compression.
#
# WHY THIS PRUNE IS SAFER THAN THE FIRMWARE ONE, not riskier. prune-firmware.txt warns that
# getting it wrong produces a machine with no network. Microcode has no such failure mode: a CPU
# whose signature is absent simply runs on the microcode its firmware already loaded. What is
# lost is the OS-side errata and security update, not the ability to boot. The rule is therefore
# the same as prune-firmware.txt's — hardware this image cannot be installed on — but the cost of
# being wrong is a degraded machine rather than a dead one.
#
# NOT TOUCHED: amd-ucode/ (0.3 MiB, all of it current AMD desktop/laptop parts, nothing to gain)
# and the amd-ucode side of the early cpio. Both classes below are Intel-only.
#
# NB on how this reaches the UKI. Stage 40 applies this list BEFORE it runs dracut, which is the
# whole point — plan/10 records that the firmware prune ran in stage 50, after dracut, and so
# never reached the UKI at all. Stage 50 re-applies it as a guard and then deletes what is left,
# because the UKI carries the only copy anything ever reads (see the assertion in stage 40).
