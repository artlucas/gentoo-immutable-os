# Branding assets (sources — the rasterised PNGs never ship, the vectors do, once)

Sources for the splash. Stage 40 renders the `*.in` templates and rasterises every SVG to PNG
with `rsvg-convert` into a **work directory**, then `make-splash-assets.py` composes those PNGs
into the artefacts that ship:

| artefact | where it goes | which window it covers |
|---|---|---|
| `splash-<ver>.bmp` | the UKI's `.splash` PE section | firmware → first modeset, blitted by `systemd-stub` |
| `splash.bin` (sprite tiles) | `/usr/share/<distro>/` on the root filesystem | first modeset → greeter, drawn by `config/splash/splash.c` |
| the theme's `images/*.svg` + `Design.qml` | `/usr/share/plasma/look-and-feel/<distro>/contents/splash/` | login → painted desktop, drawn by `ksplashqml` ([plan/17](../../plan/17-animated-splash.md)) |
| `logo.png`, `slide.png` | `/etc/calamares/branding/installer/` | the installer's sidebar and progress page ([plan/16](../../plan/16-installer.md)) |

The rasterised PNGs never enter the image, and that is still the point for the two boot-time
artefacts: they ship as pre-composited pixels, so the image needs no font, no image decoder and
no text engine before the desktop exists. The Plasma theme is the one consumer that ships
**vectors**, because by the time it runs there is a Qt session with QtSvg in it and a crisp mark
at any panel size is worth more than a tile per scale. Its slabs are re-shaded copies of these
SVGs, generated by the same script from the same constants — see "Two ways to shade one slab".

They live here rather than under `config/rootfs/` because they are build inputs, not image
content — the same reason `config/keys/` is where it is.

Everything here is text on purpose, and the reason that survived is the second one: keeping the
sources vector means the splash rescales for any panel instead of being pinned to one resolution.
It used to be enforced by accident as well — `tests/run-tests.sh` byte-scans the tree for CR
bytes, and every PNG ever written begins `\x89PNG\r\n\x1a\n` — but that scan now skips binary
files, because it is a check about *line endings* and a file with no lines has none to get wrong.
The repo does carry one committed raster, and it is not here: the live medium's single wallpaper,
`config/calamares/system/wallpaper` (plan/20 §2.1), which is a photographic gradient rather than
a mark and has nothing to gain from being a vector.

| file | what it is |
|---|---|
| `slab-{top,mid,bot}.svg` | one slab of the logomark each, on an identical `0 0 64 64` canvas so the PNGs stack in register. Face opacities 0.6 / 1.0 / 0.82 and the teal fill are baked into the alpha channel; the theme's `SetOpacity()` multiplies on top |
| `wordmark.svg` | "immos" in Archivo Bold, **glyphs converted to `<path>`** — see below |
| `status-left.svg.in` | bottom-left field; `@SPLASH_STATUS_LEFT@` is composed in stage 40 from `UPDATE_CHANNEL` and `VERSION` |
| `status-right.svg` | bottom-right "PRESS ESC FOR DETAILS" hint |
| `outline-wordmark.py` | the one-time generator for `wordmark.svg` (not run by the build) |
| `make-splash-assets.py` | composes **every** shipped artefact from the sources above. Run by stage 40, after the rasterise pass |

`make-splash-assets.py` produces all of them from one `build_block()` on purpose. The pieces meet
on screen at two hand-offs — the first modeset, and the login after it — so any drift in geometry
or brightness between them shows up exactly there, as a jump. It also holds the layout constants
(`MARK_BOX`, `GAP`, `PAD_X`, `PAD_Y`) that used to be duplicated in the Plymouth theme script,
and the three animation constants (`PULSE_CYCLE_MS`, `PULSE_DEPTH`, `PULSE_SLOTS`) that the C
splash and the QML splash both run.

## Two ways to shade one slab

The slab SVGs carry their 3D shading as polygon `opacity` over a single teal fill. That reads
backwards in a frame at rest — the top face is the largest surface and would be the dimmest — so
everything the build emits re-shades: same three faces, but the shading carried in **colour** at
full opacity. `FACE_SHADE` in the generator is the only statement of it.

It is applied twice, because the two splashes consume different things:

- `reshade_slab()` rewrites **pixels**, through a 256-entry LUT keyed on the baked alpha. This is
  what the stub bitmap, the sprite tiles and the installer images are made of.
- `reshade_svg()` rewrites **vectors**, replacing each polygon's `opacity` with the shaded fill.
  This is what the Plasma theme ships.

They agree by construction, not by luck: `rsvg` gives a polygon with fill *F* at opacity *p* an
alpha of `coverage * p`, so the LUT's `alpha / face` is exactly the coverage the flat-fill
polygon renders with. What could still drift is the *colours*, and
`tests/test-splash-assets.sh` compares them face for face with no rasteriser and no tolerance.

## The block is cut into pieces

`splash.bin` no longer carries the centred block as one tile. The logomark's box is sliced into
one horizontal band per slab (on the fixed lines in `BAND_EDGES`, with an assertion that each
slab's ink really does land inside its own band), so the KMS splash can dim one slab without
touching the other two. Each piece records the **block** as its box and its own position inside
it, which is what makes the pieces land back exactly where the flat block had them — the offline
suite reassembles the container and requires the result to equal `build_block()` byte for byte.

Assets are authored at the **1920×1080 design baseline** in CSS pixels and rasterised at 4×
(`BRANDING_ZOOM` in `scripts/lib/common.sh`); the generator divides by its own `ASSET_ZOOM`.
Do not change the zoom in one place only — `tests/test-splash-assets.sh` asserts the two agree.

## Design provenance

Two handoffs from the Immos Design System, and they resolve the same tokens to **different
themes**. That is deliberate and it is the thing to understand before changing either.

**The boot splash** → `project/templates/bootsplash/Bootsplash.dc.html`,
`project/components/feedback/Spinner.jsx` (animation "B · Layer pulse"),
`project/assets/logomark.svg`, `project/tokens/{colors,semantic,theme-palettes}.css`.

Resolved token values (**dark** theme, teal accent): background `#0a0d11` (`--surface-sunken`),
logomark `#0e9c8a` (`--accent`), wordmark `#f6f7f9` (`--text-strong`), status text `#66707f`
(`--text-subtle`).

**The installer** (plan/28) → `project/Immos Installer.dc.html` and the same token files, resolved
to the **light** theme with the teal accent. It is transcribed into
`config/calamares/qml/Theme.qml`, and the table below is the second copy of those values —
`tests/test-installer.sh` requires every colour literal in that file to appear here, so a shade
invented on one page fails the offline suite rather than shipping unexplained.

`--surface-overlay` is `rgba(13,17,22,0.45)` and is written as a `Qt.rgba()` call rather than a
hex literal, which is why it is not in the table's shape.

**The two grounds.** `logo.png` and `slide.png` are composed by `make-splash-assets.py` from the
same `build_block()` as the boot splash, but they are flattened onto the **installer's**
`--surface-page` rather than the splash's `#0a0d11` — because they are pasted into a light window
and a dark rectangle behind the logomark is exactly what "no visible edge" was supposed to
prevent. So the claim above that all consumers share one layout function still holds; what they no
longer share is the colour underneath. `--bg` is the argument that says which, it defaults to the
splash's dark, and `tests/test-splash-assets.sh` pins both.

**Archivo is substituted, not shipped.** The design system's display face is Archivo. Gentoo does
not package it, and the only Archivo in this repository is the outlined wordmark below — which
exists so that the build needs no font binary at all. Rather than add a font package with a
network `SRC_URI` for the sake of nine headings, `Theme.qml`'s `fontDisplay` is **IBM Plex Sans**
and weight carries the emphasis. `media-fonts/ibm-plex` is on the installer medium and nowhere
else (`config/portage/sets/installer`), and stage 50 §3n keeps only the Sans and Mono families.

## Regenerating the wordmark

Archivo is not packaged in Gentoo, so the wordmark is outlined **once**, by hand, and the
result is committed — that is what keeps the build font-free. Redo it only if the brand
wordmark changes:

```sh
pip install fonttools
curl -sL -o archivo.zip \
  https://github.com/Omnibus-Type/Archivo/archive/refs/heads/master.zip
unzip -o archivo.zip 'Archivo-master/fonts/ttf/Archivo-Bold.ttf'
python3 config/branding/outline-wordmark.py \
  Archivo-master/fonts/ttf/Archivo-Bold.ttf > config/branding/wordmark.svg
```

Archivo is OFL-1.1 (Copyright 2020 The Archivo Project Authors). Only glyph outlines end up in
the repo, and the font binary is never redistributed.

The status bar is set in IBM Plex Mono, which **is** packaged (`media-fonts/ibm-plex`, stable
amd64, OFL-1.1) — the builder installs it for `rsvg-convert` to find, and it does not enter the
image. Those two SVGs deliberately use an over-wide canvas with the text anchored to the edge
the splash aligns that field to, so nothing depends on knowing the font's advance width: the
surplus canvas is transparent and always falls towards the screen centre.
